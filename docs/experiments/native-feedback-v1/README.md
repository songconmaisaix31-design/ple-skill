# N/O 原生补丁拒绝反馈实验

## 结论

停止当前候选（`stop_candidate_no_gain`）。六个整对、十二个实验臂都通过文件级独立重评；基线 `native-patch` 与候选 `native-feedback` 的宏平均分均为 `0.0`，三次重复的跨题配对差均为 `0.0`，配对差样本方差为 `0.0`。

候选六臂都真实收到登记的结构化拒绝反馈，基线六臂均未收到。34 个反馈事件及其工具结果逐条匹配；31 个在第 395 秒前完成的立即重试全部语义等同于被拒绝的原补丁，另外 3 个最终重试在截止时尚未返回。候选的 65 个 `replace_line` 响应和基线的 58 个响应均满足参数 schema，但全部带有前导缩进，宿主接受数为 0；其表达式仍对整数泵水量做下标访问。

这一结论只衡量同一冻结 TypeError 下的条件恢复能力，不是正式 PLE 开发集成绩。正式开发集仍因受限数据授权失败而没有有效分数。

## 独立校验

`verify_native_feedback_evidence.py` 不信任运行时汇总，直接从 `evidence.zip`：

1. 校验提交、协议与输入哈希、配对顺序、种子、250/395 秒时钟；
2. 逐请求确认两臂只有必选 `replace_line`、相同 schema 和 96 token；
3. 确认候选工具结果只有 `accepted=false` 与登记原因码，并与原调用及下一次重试对应；
4. 从归档的输出文件重新运行评分逻辑，核对运行时分数；
5. 统计实际补丁参数、宿主接受、反馈曝光和重试重复率。

重放结果为 12/12 transcript 完整、12/12 请求形状有效、12/12 源码与时间有效、候选反馈曝光 6/6、基线 0/6、34/34 反馈 payload 有效、0 个补丁被接受。

## 判定

预登记要求三个重复的跨题宏配对差全部严格大于 0，且 N/O 各自平均差非负。实际三个宏配对差均为 0，因此即使覆盖条件全部满足，也必须停止当前原因码反馈候选。

结果定位了更具体的瓶颈：模型能够稳定路由到原生工具，也确实看到了工具拒绝，但机器式原因码没有改变它的编辑动作。下一轮如果继续，应只检验“可执行的人类可读纠正指令”是否优于当前原因码，不能同时放宽守卫或改变工具 schema。
