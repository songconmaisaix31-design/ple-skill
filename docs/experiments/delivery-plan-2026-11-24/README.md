### 开发诊断与 Kaggle 提交的边界

这两项登记都使用 GitHub Actions 上自托管的 Unsloth 量化权重。官方 kit 允许用兼容代理在开发端运行；赛事要求 harness 实际调用声明的赞助模型。尚无证据认定该第三方量化端与官方模型相同。即使获得可重评的文件，也仅归档为开发诊断。提交用的产物须由已核实的赞助模型重新生成。保留实际服务提供方、请求和响应模型标识、运行与用量记录（不含密钥），再对该产物运行官方审查、从文件复评及 kit check。优先使用已授权并核实的端点。若切换模型或精度，另立基线；此前自托管产物不能混入参赛包。[官方模型与代理](https://github.com/google-research/ple/blob/8320f0402fdca9f42476607f72bcfd5271cd50c9/docs/models.md) · [公平竞赛要求](https://github.com/google-research/ple/blob/8320f0402fdca9f42476607f72bcfd5271cd50c9/docs/rules.md#fair-play)

### 研究如何影响实验选择

| 原始研究 | 观察与本项目的决定 |
|---|---|
| [Han 等，PLE，第 3.2、5.1 节](https://arxiv.org/html/2610.30537v2) | 工程任务要求提交具体文件，部分任务还检查跨文件约束、物理可行性和来源。在论文的实验中，正常终止但没有可评分交付记零。我们分别报告文件捕获、结构检查和官方内容分。 |
| [Chan 等，MLE-bench，ICLR 2025，表 2 和附录 A.6](https://arxiv.org/pdf/2410.07095) | 在 75 项 ML 工程竞赛上，GPT-4o + AIDE 的生成提交、提交有效、取得奖牌三项比例分别为 70.7%、54.9%、8.7%。AIDE 的适配会追踪目标文件是否实际生成。这里用文件身份及独立重评验收，生成空壳无法证明内容正确。论文没有测试本项目的第四回合提醒。 |
| [Yang 等，SWE-agent，NeurIPS 2024，表 3](https://proceedings.neurips.cc/paper_files/paper/2024/file/5a7c947568c1b1328ccc5230172e1e7c-Paper-Conference.pdf) | 在 SWE-bench Lite 上，逐条展示搜索匹配的解题率为 12.0%，摘要式搜索为 18.0%。作者观察到逐条翻阅有时耗尽预算。我们保留现有搜索和模型，只在观测到缺件时提醒转向实际写入。文献中的百分点不用于预测 PLE 分数。 |

[36 个真实 Gemma 实验臂的文件重评与时间图](../delivery-timing-2026-11-24/README.md)显示，8 次满分交付都在第二个获准修补后产生。36 臂的评分来自第 395 秒保存的文件。成功执行返回时间只给出写完文件的上界。数据来自原创调度题，正式 wind 的读取、写入和捕获顺序仍以云端运行证据为准。

### 预登记 A · 换一道正式题，固定全部生成行为

先等待第六轮结束并保存原始尝试。已有可独立重评的交付时，先完成开发证据包，并转向已核实的赞助模型重新生成参赛产物。若第六轮有正式观测且无法交付，先诊断最早可见的断点，再在以下固定条件下测一个新的正式基线。若该失败是两题共用的基础设施故障，先修复该故障。

- 事先按[冻结的官方清单](https://github.com/google-research/ple/blob/8320f0402fdca9f42476607f72bcfd5271cd50c9/eval/dev_set.yaml)的原顺序选择第一个仅用规则检查、只交一个 Python 文件的任务，即 `data-hall-mep-routing`。并列合格的另一题不运行。这样可验证确定的文件和计分链路，无法预判工程问题是否更容易。
- 唯一变化是任务。生成端取第六轮运行源码 `35306a8edc3e053a6b67a8e8701ad2caeb168e08`，保留上下文管理、工具、提示、权重与采样，ZIP 提醒关闭。用旧入口及新入口分别重构，第六轮的提交用 harness 都为 `4436487f79fb4d898c191894c9aa11f5210d697f`，Git 树同为 `f5bd5abd5af01e7684d51421e272ff96a4496abe`。最终参赛包另含交付，其提交 SHA 单独记录。
- 官方 kit 为 `8320f0402fdca9f42476607f72bcfd5271cd50c9`，数据版本 `b3857a3fea39a695e18f845d4a88f29442e96e75`，新任务树 SHA-256 为 `4f11a0a62f11c2b0ea6347d7281a6297eed83087d1ae83d5cc42a9dd79f1c940`。Gemma 4 26B A4B，UD-IQ2_XXS，权重 SHA-256 `52f98e6fc6df62438dff8f57ac049f60b4c36acf93786b6aeeedc129acc02343`；llama.cpp b12651，16,384 上下文、温度 0、种子 17、单槽、至多四个 CPU 线程。评分使用任务自带确定性检查器。
- 一次生成、有交付才做一次独立重评，作业、生成和重评上限为 360/260/60 分钟。核对实际源提交、依赖及输入哈希；缺项单列。真实非空指定文件须出现在官方捕获与清单中，公开导出的相同字节须在独立容器被重放，生成分和文件分均已实测且一致。满足则完成该题可交付性验证，进入打包与材料核验；两次一致的零分仍是内容零分。失败保留证据，停止扩展该入口。不同正式题是覆盖，不计算跨题策略增益或单次样本方差。
- 运行仅使用新单题的精确触发标题 `Run official PLE export single data-hall-mep-routing`。其他 28 题不会随此入口排队。后续核对已有运行、attempt 及官方收据，避免重复提交。

### 预登记 B · 单次 ZIP 写入提醒

这是候选实现及软件对照。第六轮正常结束并归档前、或 A 尚在途时，不启动新的 wind 模型请求。先评估 A 的实际交付与提交条件。只有 wind 第六轮能确认至少四轮模型返回、最终仍缺少目标、且排除基础设施中断时，才考虑与同任务基线进行一次可交付性试跑。已取得赞助模型的可提交包时优先提交。

- 模型可正常读取和写入。只在第 4 个完成的模型回合结束、做过除 finish 以外的动作且合同明确指定 ZIP 时，执行一次上限三秒的只读探测。现场确认路径缺失才加入固定提醒，让模型根据已读取的材料生成一项真实成果并继续完成其余内容。不会由宿主补写内容。第 4 回合是事先选择的低成本检查点，最优触发时机未知。
- 基线关闭 `PLE_EARLY_ZIP_WRITE`，候选设为 `1`。其余策略沿用第六轮；实际对照应在同版本上固定输入 `848ac589c41d55ffcd364b6fef9f1dff196c3cc6067a2e630ea0807c818fc5ef`、模型、种子、预算与评分程序。区分提醒已加入、携带提醒的请求已成功返回、已捕获真实 ZIP、语义文件分四项。第六轮仅作历史参考。
- 初次候选一次且只判可交付性。确认提醒已成功返回、规则生成分和独立文件分均实测一致并大于零，才登记同机三次配对估计收益。文件有效但分数为零可用于流程核验；无得分改善则停止扩大提醒策略。提醒未送达或关键观测缺失记证据不足。不能将脚本模型或跨任务成绩计入增益。
- 十个原创脚本用例通过生产 harness 及官方 capture 验证分支。相同动作历史的两臂产出逐字节相同的 ZIP。正确净重 199 kg 与误填毛重 234 kg 的 ZIP 都能打开，规则检查只给前者 1 分。脚本已定义模型如何反应，这些用例只验证程序、捕获与复评。[逐项记录](early-zip-controls.json) · [复现脚本](../../../devtools/early_zip_control.py)

原创控制的实际捕获副本可直接检查：[净重正确的 ZIP](controls/correct.zip) · [结构正确、数值错误的 ZIP](controls/wrong-value.zip)。两份哈希均在逐项记录中。
