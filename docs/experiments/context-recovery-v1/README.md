# 中途上下文拒绝与交付恢复

### 原创对照的实际结果

两项对照均使用生产 harness，在临时任务目录执行程序和读写文件。模型返回由脚本固定。这些数字仅用于验证程序行为。

| 观测 | 结果 |
|---|---|
| 原创输入的三项观测值 7、4、12 | 脚本模型调用生产 run_python，在指定位置生成 145 字节 ZIP。固定官方 kit 的 capture 复制了 1 个文件。重新打开复制件，CRC、成员、数量 3 与总和 23 均正确。 |
| 同一 ZIP 任务，跳过写入 | 守卫报告 FAIL，捕获 0 文件。 |
| 原创求和任务的第二次请求遇到结构化上下文拒绝，恢复关闭 | 2 次请求，1 次成功返回，最终文件缺失。 |
| 相同拒绝和中间磁盘状态，开启恢复 | 6 次请求，5 次成功返回。恢复后重新读取已算好的小计，验证最终文件中的总和为 25。 |
| 其余 8 项异常对照 | 首次请求被拒时沿用原错误；连续或稍后再次拒绝时最多恢复一次。无关 400、异类型、计数矛盾、403 和截断消息均未引发恢复。 |

[ZIP 对照原始输出](zip-control.json) · [十项恢复对照原始输出](recovery-control.json) · [固定的官方 kit](https://github.com/google-research/ple/tree/8320f0402fdca9f42476607f72bcfd5271cd50c9)
