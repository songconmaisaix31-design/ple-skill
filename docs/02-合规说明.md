## 1. 规则边界（原文要点）

> *Do not hard-code task answers or detect specific tasks to branch on them, dev tasks included. The dev-set graders and reference files are public so you can evaluate locally, and **your harness must never read or use them**. A harness that reads its own `artifacts/` at build or run time (from disk, git history, or the network) breaks this rule.*

> *Your committed `artifacts/` must be exported by `eval/run.py` from the harness you submit, running the `model_api` declared in `submission.yaml`.*

关键区分：**公开 dev set 允许用来开发和本地评估**，但「harness 本身」不得读取或使用 dev graders / reference files，也不得按具体 task 分支或硬编码答案。

## 2. 运行时文件白名单

`serve.py` 及其 import 链实际会读取的仓库文件只有：

| 类别 | 路径 |
|---|---|
| 入口 | `serve.py`、`submission.yaml`、`requirements.txt` |
| 运行时代码 | `skillkit/*.py`（harness / transport / model / guard / specgen / router / harness） |
| 注入模型的上下文 | `skills/_shared/SKILL.md`、`skills/<domain>/SKILL.md`、`skills/<domain>/checklist.md`、`skills/_shared/validate.py` |

**不在运行时路径**：`docs/`、`writeups/`、`devtools/`、`HANDOFF.md`、`README.md`、`GOAL.md`、`criteria.py`、`dryrun.py`。这些是开发期工程笔记与离线判据，`serve.py` 及 `skillkit/` 从不打开它们。

> 因此，`docs/` 里出现的历史数值、`devtools/wsl-run.sh` 里的示例 task id、以及 `writeups/` 的技术叙述，**不会进入模型上下文，也不参与 build/run**。但为降低评审疑义，本次仍把 `writeups/` 里的 dev task id 全部中性化为领域描述。

## 4. 保留内容的边界

`skills/*/SKILL.md` 里仍保留 CSV 列头、工作表组名、章节骨架、模板套用规则。这些是**公开的工程文档格式惯例**（「这类文件长什么样」），不是任何题目的工程结论或答案数值。本次已把其中所有具体取值、项目文号、人名、日期替换为占位符或通用描述，并在 `_shared/SKILL.md` 第六节写明禁止项。

`criteria.py` 的 `load_tasks()` 仍可读取外部 `ple-template/artifacts` 做离线回归 —— 这是官方允许的 **local evaluation**，且只在开发者手动执行 `criteria.py --template <path>` 时发生，评测容器不会执行它。
