## 2. 本机实测暴露的问题

```
python criteria.py     → GATE-A FAIL (8/10)，但 G-05/06/07 是 0/0 假 PASS
                         G-08 BLOCKED（找不到 baseline artifacts）、G-09 FAIL
python dryrun.py       → exit 1，steps=6，file exists=False
                         guard: ERROR ×3 熔断
                         python3: can't open file 'C:\tmp\ple_validate.py'
```

根因归类：

| 类别 | 问题 |
|---|---|
| 真实代码缺陷 | `guard.py` 硬编码 `/tmp/...`，Windows 解析成 `C:\tmp\...`；`criteria.py` 用 `min(阈值, len(tasks))`，0 题时阈值退化成 0 导致假 PASS |
| 环境缺失（不是代码问题） | `ple-template` 缺 → 29 题题面与 baseline artifacts 全缺；本机无 `websockets` / `httpx` / `yaml`；Docker / WSL 探查被安全策略拦截 |
| 协议硬风险 | `serve.py` 的 `ping_interval=20, ping_timeout=60` 与官方要求 `ping_interval=None` 冲突（单条 exec 上限 600 s） |

注意：**Linux 评测容器里 `/tmp` 有 1 GB 且可写，硬编码 `/tmp` 不会在正式评测中炸**，只影响本地跨平台自测。真正的判 0 风险是心跳配置。

## 5. 官方 kit 侧的结论（为什么必须 WSL2）

- 克隆 `google-research/ple` 到 `_ple_meta/ple-official`。
- `kit/build.py` import `fcntl` → Windows Python 直接 `ModuleNotFoundError`，`uv run python -m kit validate` 跑不了。
- `docker build` 用路径 context，Docker-in-Docker 不可行。
- `eval/README.md`「Platform notes」明确：Windows 必须全程在 WSL2 的 Linux 文件系统（`~` 下，不是 `/mnt/c`）里跑，用 WSL 的 git / uv / Python；`/mnt/c` 下常见 `core.symlinks=false`（kit check 拒绝）和 `core.autocrlf=true`（脚本变 CRLF，Linux bash 崩）。
- 官方 `files` 阶段要求：install/serve 脚本 LF、无 API key/private key、无 LFS、symlink 正确检出、子模块可匿名拉取、**entry 是仓库根目录且一切已提交**。
- 官方 `eval/run.py` 参数核对：`--env-file`、`--tasks`、`--trials`、`--attempts`、`--tasks-dir`、`--no-export`、`--artifacts`、`--regrade`；`kit check` 支持 `--env-file`、`--no-smoke`、`--cancel-test`、`--keep`、`--rebuild`、`--work`。`--no-smoke` 的检查按设计**不会**打印 `ready to submit`。
- `kit/model_proxy/start.sh` 需要 `VERTEXAI_PROJECT` + `MODEL_PROXY_KEY`，默认 bind `0.0.0.0:4000`；Linux 上 Docker bridge 连不到只绑 `127.0.0.1` 的服务。
- judge 优先级：`JUDGE_BASE_URL`+`JUDGE_API_KEY` → `MODEL_PROXY_URL`+`MODEL_PROXY_KEY`（本项目这条）→ 自有模型 key；`JUDGE_MODEL` 默认 `claude-opus-5-5`。
